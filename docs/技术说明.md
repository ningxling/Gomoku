# 五子棋：传统 AI + 强化学习 AI，训练在 VM 上跑、权重定时回传

网页一种打三种模式：

| 模式 | 说明 |
| --- | --- |
| 人人对战 | 两个人轮流点棋盘 |
| 人机对战 | 你 vs AI，AI 可以选**传统搜索**或**强化学习** |
| AI 对战 | 传统搜索 vs 强化学习，自动对局、可暂停，用来观战/对比 |

## 1. 怎么玩

```
双击  开始游戏.bat                  → 打开 http://localhost:8000
或    cd gomoku && python play_all.py          （默认：传统 1.2s/步，强化 400 次模拟）
      python play_all.py --time 2.5 --sims 800
```

- 下拉框「AI: 传统搜索 / 强化学习」只在**人机对战**里生效；
- 选「AI 对战」时会出现「黑: 传统搜索 / 黑: 强化学习」——决定谁先手，白方自动用另一个；
- 棋盘下方灰字显示上一步 AI 的搜索信息（深度/节点数/耗时，或模拟次数），一眼看出是谁在下；
- 「禁手」勾选框对 AI 也生效；9/15/19 棋盘随时换，不用重启服务器；
- AI 对战模式下有「暂停 / 继续」。

```
cd gomoku && python test_engine.py     # 棋规、禁手、算杀、自对弈、两种引擎、AI 对战流程
```

## 2. 两个 AI

| | 传统搜索 (ab) | 强化学习 (nn) |
| --- | --- | --- |
| 本质 | negamax + α-β + 棋型评估 + 威胁表 + VCF 算杀 | MCTS + 策略价值网络（AlphaZero 风格） |
| 依赖 | 纯 Python 标准库 | torch + `checkpoints/latest.pt` |
| 每步 | 19×19 约 1~2 秒 | 400 次模拟，1~2 秒 |
| 强度 | 现在更强 | 训练中，还打不过传统引擎 |

传统引擎结构：

```
落子 → 增量窗口棋型评估(O(1)) → 威胁表（谁能下一手成五）
      ├─ 我有四点 → 直接赢；对方有四点 → 只能挡，多于一 → 已输
      └─ VCF 算杀（连续冲四）→ 没杀 → α-β 迭代加深（置换表 + 进攻/防守排序）
```

禁手（长连/四四/三三）用严格版判定（识别跳三、跳四），比网页自带的连续型判定更严，
所以 AI 不会下出网页不认的禁手点。

## 3. 训练在 VM 上跑，本地定时回传

**训练主力在 VM**（`rocky@10.129.245.205:/home/rocky/gomoku`，4 核 / 3GB，torch 2.8+cpu），
本地只负责：定时看进度 + 把最新 `latest.pt` 拉回来给网页用。

### 3.1 VM 上的训练现在长什么样

**纯 19×19 训练**（10-20 晚切换）：样本全部落在目标棋盘上。

```
run_train.sh:
  python3 train.py --curriculum "19:0" --sims 60 --episodes 8 --buffer 8000 \
                   --epochs 3 --teacher-games 6 --teacher-time 0.10 \
                   --tactical-guard 1 --max-moves 150
```

- `--tactical-guard 1`：自我对弈时“能成五 / 唯一挡四”直接走，不跑 MCTS —— 这些位置的 π
  是精确标签，同时避免对局 10 手就崩；
- `--max-moves 170`：单局手数上限。不设上限时会出现 284 手/局的对局，单轮跑到 885 秒。
  实测 19×19 到 **150~155 手**时棋盘密度（~42%）已经足够让轮到的一方凑出 3~4 步 VCF，
  所以 cap 定 170 能让绝大多数对局自然下完、拿到真实 z（引擎双方对下验证过：VCF 是真杀）；
- **截断局不标“和棋”**：`_bootstrap_value()` 用传统引擎在截断局面上的搜索值当目标
  （算到强制胜就约 ±1，否则按棋型估值 tanh 压到 (-1,1)）。早期标 `z=0` 导致价值头学会
  “所有局面都是 0”（value loss 塌到 0.1），对局全磨到上限，自己强化自己；改成 bootstrap 后
  value loss 回到 0.95 左右（目标变成真 ±1）。现在 cap=170，bootstrap 只当兜底；
- `--teacher-games 6`：因为自我对弈大多是“截断的和棋”（z=0），价值头见不到胜负，所以把老师
  对局从 3 局加到 6 局——老师对局是**分胜负**的，给价值头灌真 ±1 标签，约占 buffer 30%；
- 每轮日志会打印`对局: 黑胜 x / 白胜 y / 和 z / 截断 w | 平均 N 手/局`，用来盯“和棋均衡”有没有缓解；
- 实测（episodes 8 + cap 150）：**340~400 秒/轮**，8 局 × 约 130 手；
- 9×9 那侧暂停了：要补就 `--mix-sizes "9:1,19:2"` 跑一两小时；
- 日志：`train.log`（stdout，干净）、`train.err`（NNPACK 之类警告）；
- 备份：`train.py.bak`、`run_train.sh.bak`、`checkpoints/latest.pt.pre_*`；
- 换配置：改 `run_train.sh` 后执行 `./restart_vm.sh`（会自动备份当前权重、停旧进程、重启并打印状态）。

### 3.2 关于“胜率要在 19×19 上”

- 网络是全卷积的（策略头 1×1 卷积、价值头全局池化），权重与尺寸无关，9×9 学的棋形能迁移；
- 但 19×19 的空旷程度、开局节奏、价值尺度都不一样，**只用 9×9 训出来的网络在 19×19 上明显偏弱**；
- 这个模型只有 3 个输入通道（己方/对方/先后手），没有“棋盘尺寸”这个特征，混训会有轻微分布冲突。

所以现在**只喂 19×19**。之前短暂用过 `9:1,19:2` 的混训（2/3 在 19×19），那样 19×19 的样本
产能会低约 25%，在“只要 19×19 的胜率”这个目标下不划算，已切回纯 19×19。

### 3.3 本地回传

```
python sync_vm.py                 # 查一次：进度 + 有新权重就拉回来
python sync_vm.py --loop 7200     # 每 2 小时一次（也可以双击 定时同步权重.bat 挂着）
```

每次会：

1. ssh 读远端 `latest.pt` 的 mtime/大小、`train.log` 最后一条 iter、训练进程是否在跑；
2. 变了就 scp 到 `checkpoints/latest.tmp` 再原子替换 `checkpoints/latest.pt`，
   并在 `checkpoints/history/` 留最近 5 份；
3. 终端打一行进度，同时写 `checkpoints/vm_status.json`。

例：

```
[20:44:22] | 第 470 轮 | 19x19 | loss 4.624 | 训练中 | → 已回传最新权重 1187 KB
```

`server_all.py` 每次用强化学习引擎前都会看一眼 `latest.pt` 的 mtime，变了就自动重新加载，
**不用重启服务器**，网页刷新一下就是新模型。连不上 VM 会重试 2 次后明确报错。

> 想让它开机自启：`定时同步权重.bat` 丢进「启动」文件夹，或在「任务计划程序」里建一个
> 每 2 小时运行一次的任务（指向 `sync_vm.py --once`）。命令行 `schtasks` 建任务在我这边
> 被权限挡了，所以默认用“后台循环 + bat”这种方式。

### 3.4 权重存档（只在 VM 上，不依赖本地电脑）

训练机一直在跑，本地不一定开机，所以**存档放在 VM**：

```
checkpoints/archive/
    iter00516_9x9_20261020_1325.pt        ← 权重快照
    index.csv                              ← 时间,轮数,棋盘,loss,字节,训练命令
```

- 由 `snapshot_ckpt.py` 每 30 分钟打一份（先复制、校验 zip 完整、再改名，不碰训练进程正在写的文件）；
- 同一轮只存一次；最多保留 400 份（约 480 MB，VM 还剩 69 GB）；
- `index.csv` 里记了当时的**训练命令**，以后回看就知道这份权重是什么配方训出来的；
- 重启 VM 后一条命令把训练和存档都拉起来：`./start_all.sh`（已在跑就跳过，重复执行无害）。

以后做"不同训练时长对比"时，直接拿两份存档对打：

```
python duel.py --ckpt checkpoints/archive/iter00516_9x9_20261020_1325.pt \
               --against checkpoints/archive/iter03000_19x19_20261022_0900.pt \
               --size 19 --games 40 --sims 100
```

（`duel.py` 之前就支持 A vs B，不用改。）

### 3.5 自动基准赛（胜率曲线）

每次回传成功后，本地会自动让新权重和传统引擎打 6 局（**19×19**、交替先后手、禁手开、
网络 60 次模拟 / 老师 0.1 秒），结果追加到 `checkpoints/bench_log.csv`：

```
python sync_vm.py --loop 7200 --bench 6      # 定时回传 + 自动测胜率
python bench_vs_teacher.py --games 20 --size 19 --sims 60 --time 0.1   # 手动打一轮
```

CSV 列：时间、轮数、棋盘、模拟次数、局数、老师胜、网络胜、和、网络胜率、Elo 差。
用 Excel 直接打开不会乱码（写了 BOM）。

当前基线（接手时的旧权重）：

| 时间 | 轮数 | 棋盘 | 局数 | 网络胜 | 胜率 |
| --- | --- | --- | --- | --- | --- |
| 20:53 | 470 | 9×9 | 8 | 0 | 0% |
| 20:59 | 481 | 19×19 | 6 | 0 | 0% |

注意：6~8 局只能看趋势，真正的“客观胜率”至少 40~60 局面才有统计意义，
到时候把 `--bench` 提到 40 打一次。

## 5. 接口

```json
POST /move
{"board": [[0,1,-1,...], ...], "player": 1, "engine": "ab", "forbidden": true}
→ {"move": 12, "row": 1, "col": 3, "engine": "ab",
   "info": {"reason": "α-β", "depth": 7, "nodes": 23040, "sims": 0, "think": 0.51}}
```

`move/row/col` 与 kimi3 原来的 `server.py` 完全一致，老服务器照样能配这个网页；
`engine`/`forbidden`/`info` 是新增的，旧代码会忽略。另有 `GET /info` 报告两个引擎是否可用、
当前权重路径和 mtime（网页据此灰掉不可用的选项）。

## 6. 已知限制

- 传统引擎是纯 Python，19×19 每步 1~2 秒到顶；想再强要换 C++/位棋盘。
- 强化学习模型还弱：策略价值网络只有 64 通道 4 个残差块，VM 上 60 秒一轮，
  目前仍打不过传统引擎（被 4:0）。
- AI 对战在 19×19 + 400 次模拟下每步约 2 秒，一局要几分钟，属正常。
