1. 项目概述

面向"想下一盘五子棋、又想看看不同 AI 谁更强"的场景，实现了一个浏览器里可玩的五子棋项目：

  • 传统搜索引擎：α-β 迭代加深 + 棋型评估 + 威胁表 + VCF 算杀 + 禁手判定，纯 Python 手写；
  • 强化学习引擎：AlphaZero 风格（策略价值网络 + PUCT MCTS + 自我对弈），30 万参数；
  • 三种对局模式：人人对战、人机对战（可选引擎）、传统 vs 强化自动观战；
  • 训练流水线：远程训练、权重回传、基准赛、健康监控、权重存档。

选择它的理由是：五子棋同时适合经典搜索（能把手写的 α-β 做到可量化的强度）和学习和搜索结合 （AlphaZero），两者放在同一界面里对比，能把课程里的搜索、剪枝、哈希、树结构一次讲清楚。

2. 核心设计（课程知识）

2.1 数据结构：长度-5 窗口 + 三进制编码

19×19 在 4 个方向共 1020 个"长度 5 的窗口"，每个窗口用 5 位三进制编码（0 空 / 1 黑 / 2 白）， 编码值 0~242 直接当作查表下标：

表用途
_TB[243] / _TW[243]窗口分值：成五 10⁷、四 2000、活三 200、二 20
_FOUR_MASK[243]该窗口是否"4 子 + 1 空"（即存在成五点）

关键性质：落子只影响 20 个窗口（4 方向 × 5），所以评估是 O(20) 增量更新，不需要重扫棋盘。 这就是纯 Python 也能跑到 1~2 万节点/秒的原因。

2.2 威胁表：把"强制着法"从搜索里摘出来

维护 tcnt[player]：记录"哪些空点能让该方下一手成五"。窗口变成"4 子 + 1 空"时对空位 +1， 破坏时 -1。于是每个节点 O(1) 判断：

  • 自己有冲四点 → 直接判必胜，不搜索；
  • 对方有冲四点 → 只能挡（唯一挡点只搜一手）。

2.3 搜索

negamax + α-β + 置换表（Zobrist，EXACT/LOWER/UPPER）+ 迭代加深（2→10 层，超时回退）+ 候选点按"进攻分 + 0.9×防守分"排序 + 叶子节点强制着法延伸 + VCF 连续冲四算杀。

2.4 复杂度

操作代价
落子 / 撤销O(20)
静态评估O(1)
单点排序分O(20)
威胁表维护O(40)
单节点总体约 50~80 μs（实测 1.2~2 万节点/秒）

3. 实验与结果

3.1 消融实验：三个部件各值多少

19×19、限时 0.3 秒、3 个安静开局取平均；9×9 快棋 0.05 秒/手、各 8 局交替先后手。 完整脚本：tools/ablation_engine.py，输出：docs/ablation_result.md。

配置平均深度节点数耗时对完整版胜率
完整版5.05,973312 ms—
去掉置换表5.05,888307 ms38%
去掉 VCF5.06,059306 ms50%
去掉威胁表2.72,901313 ms25%

结论

  1. 威胁表贡献最大：同样 0.3 秒，深度从 5.0 掉到 2.7，胜率掉到 25%。它砍掉的是"必须应"的分支。
  2. 置换表在这个深度下没有可测收益（5973 vs 5888 节点）——诚实记录：它的价值要在更深搜索中体现。
  3. VCF 只影响"能否算出强制胜"（战术表里唯一失效项），对 9×9 快棋胜率影响不大。

3.2 强化学习 vs 传统引擎

19×19、每局随机 4 手开局、网络 60 次模拟、传统引擎 0.1 秒/手：

12041225%

强化模型训练了约 1300 轮（每轮 8 局自我对弈），policy loss 从 3.1 降到 1.1。

3.3 一个方法论错误（值得记录）

早期基准赛用 6 局，出现"16.7% 胜率"。后来发现两个 agent 都是确定性的， 6 局其实是同一盘棋重复 3 遍（执黑 3 局、执白 3 局），真实分辨率只有 2 盘。 加上"每局随机 4 手开局"后才得到上表可信数据。

5. 局限与改进

  1. 强度：强化模型对传统引擎约 20%。瓶颈是"看不见两级威胁"（活三→活四），

60~120 次模拟在 19×19 上等效深度只有 3~4 层，而 VCF 需要 6~10 层。

  1. 速度：纯 Python，19×19 每步 1~2 秒到顶。
  2. 尺寸迁移：全卷积网络权重与尺寸无关，但只用 19×19 训练，实测 9×9 胜率从 25% 掉到 8%

（感受野 19 格 > 9×9 边长，价值头全局池化尺度也错位）。

  1. 后续：把威胁表接进 MCTS（树内强制扩展）做混合体；有 GPU 后加宽网络到 128ch×8block。
